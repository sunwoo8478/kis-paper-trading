# 자율운용 v3 명세

## 개요

현재 자율운용 엔진을 단순 기술지표·LLM 제안 기반 모의투자에서 장세별 자산배분, 포트폴리오 위험 통제, 현실적인 체결, 반복 가능한 검증이 가능한 모의운용 시스템으로 개선한다.

## 목표

- 상승·중립장에서는 가용 자금을 효율적으로 투자한다.
- 하락장, 손실 한도 도달, 데이터 장애 상황에서는 현금 보유와 손실 제한을 우선한다.
- 매수하지 않은 이유와 매도하지 않은 이유까지 사용자에게 설명한다.
- 고정 슬리피지만 적용하던 모의 체결에 유동성과 부분 체결을 반영한다.
- 단일 60일 수익률이 아니라 여러 기간과 시장 구간에서 전략을 비교한다.

## 비목표

- 이번 단계에서는 실제 증권 계좌 주문을 전송하지 않는다.
- 사용자의 현재 모의실험, 잔고, 주문 이력을 초기화하지 않는다.
- 과거 성과를 미래 수익으로 보장하지 않는다.

## 운용 원칙

1. 모든 주문은 자율운용 엔진만 실행한다. 챗봇은 조회와 설명만 담당한다.
2. 목표 투자비중은 시장 국면에 따라 결정한다.
   - bullish: 95~100%
   - neutral: 70~90%
   - bearish: 0~30%
   - stale/error/halted: 신규 매수 0%
3. 종목당 비중, 업종 집중도, 유동성, 일일 손실, 누적 낙폭 제한을 주문 전에 강제한다.
4. LLM 출력은 제안으로만 취급하며, 정량 가드가 유효하지 않은 결정을 제거한다.
5. 주문하지 않은 결정도 구조화된 거절 사유로 기록한다.

## 기능 요구사항

### 장세 및 목표 노출

- 후보군의 방향성, 변동성 및 시장 지표로 장세를 분류한다.
- 장세별 목표 투자비중을 계산한다.
- 현재 투자비중이 목표보다 높으면 신규 매수를 막는다.
- 목표보다 낮고 허용 가능한 후보가 있으면 허용 범위 안에서 현금을 분산한다.

### 포트폴리오 리스크

- 기존 손절·익절·일일 손실 제한을 유지한다.
- 최대 낙폭 단계에 따라 신규 매수 중단 또는 투자비중 축소를 적용한다.
- 동일 종목 재주문 쿨다운과 사이클당 주문 수 제한을 유지한다.
- 거래대금이 부족하거나 가격 데이터가 오래된 종목은 제외한다.
- 모든 차단 사유를 `blocked_decisions`로 저장한다.

### 체결 시뮬레이션

- 수수료, 세금, 기본 슬리피지를 계속 반영한다.
- 주문 수량이 설정된 일평균 거래량 비율을 넘지 못하게 한다.
- 거래량 제한에 걸리면 부분 체결 또는 미체결 처리한다.
- 체결 결과에 요청 수량, 체결 수량, 평균 체결가와 사유를 기록한다.

### 백테스트

- 60·120·252 거래일 구간을 동일한 규칙으로 실행할 수 있어야 한다.
- 전략 수익률, 비교군, 알파, 최대 낙폭, 승률, 손익비, 회전율을 제공한다.
- 구간별 결과와 전체 판정(pass/warn/fail)을 반환한다.
- 미래 데이터 누출 없이 이전 거래일까지의 데이터로 당일 주문을 결정한다.

### AI 설명

- 다음 질문을 현재 기록으로 직접 답한다.
  - 왜 샀어/왜 팔았어
  - 왜 오늘 안 샀어/왜 아무것도 안 했어
  - 어떤 제한 때문에 주문이 막혔어
  - 현재 장세와 목표 투자비중은 얼마야
- 답변에는 판단 사이클, 근거, 차단 규칙, 조회 시각을 포함한다.
- 기록에 없는 정보는 추측하지 않는다.

## API 및 저장 변경

- 자율운용 사이클 응답에 `market_regime`, `target_exposure_pct`, `blocked_decisions`를 추가한다.
- 백테스트 비교 API를 추가하거나 기존 API에 다중 기간 옵션을 추가한다.
- 기존 데이터베이스와 호환되는 방식으로 필요한 컬럼을 마이그레이션한다.

## 오류 처리

- 시세가 오래되었거나 조회에 실패하면 해당 종목 신규 주문을 차단한다.
- 모델 장애 시 주문을 생성하지 않고 장애 이유를 사이클에 기록한다.
- 데이터베이스나 체결 오류가 발생해도 동일 사이클 주문을 중복 실행하지 않는다.

## 보안 및 운영

- API 키는 응답·로그·Git에 기록하지 않는다.
- 현재 노출된 Context7 키는 폐기·교체 대상으로 문서화한다.
- 긴급 정지 상태에서는 수동 재개 전까지 신규 주문을 실행하지 않는다.

## 승인 기준

- 기존 테스트와 신규 위험·체결·설명 테스트가 모두 통과한다.
- 하락장에서 신규 매수가 차단되거나 목표 비중 이하로 제한된다.
- 유동성 제한을 초과한 주문이 전량 체결되지 않는다.
- 미주문 사이클에 대해 챗봇이 실제 차단 또는 관망 사유를 답한다.
- 24시간 서비스 재시작 후 상태·계좌·판단 응답이 정상이다.

## 구현 순서

1. 장세별 목표 투자비중과 구조화된 차단 사유
2. 낙폭·유동성 기반 포트폴리오 가드
3. 부분 체결 모의 실행
4. 다중 기간 백테스트 리포트
5. AI 미실행 사유 설명
6. 통합 테스트와 서비스 반영
